Parte 1de 6

Prólogo: ya eres un blanco

La tienda de Laura ya tiene EC2, S3, RDS y DynamoDB. Y en internet hay bots que tocan todas las puertas, todo el día.

0.1prólogo · la superficie de ataque

Cada puerta abierta es un blanco

// como una tienda con muchas puertas a la calle

Todo lo que montamos en clases pasadas queda en internet: el puerto 22 de la EC2, los buckets, la base, la consola. Eso es tu superficie de ataque. Los bots no eligen a Laura por famosa: prueban todo, contra todos, sin parar.

Pregunta del día: ¿qué pasa si alguien logra entrar?

0.2prólogo · qué cuidamos

Lo que el atacante quiere romper

// como los tres candados de una tienda

Todo ataque rompe al menos uno: la Confidencialidad (ver lo que no debe), la Integridad (cambiar lo que no debe) o la Disponibilidad (tumbar la tienda). A esto se le llama la tríada CIA.

0.3prólogo · quién cuida qué

Responsabilidad compartida

// como el edificio y tu apartamento

AWS cuida la seguridad DE la nube: edificios, servidores, red física. Laura cuida la seguridad EN la nube: sus datos, sus usuarios, sus puertos y el sistema operativo de su EC2. Si deja la puerta abierta, AWS no la cierra por ella.

// como murallas, fosos y guardias: si una falla, queda la siguiente

Laura no confía en una sola protección: arma su castillo por capas. Esta noche la van a atacar por cada una… y en cada capítulo veremos qué la salvó.

Capítulo 1: el correo de las 21:12

El primer ataque no va contra los servidores: va contra las personas.

1.1cap. 1 · identidad

El correo de las 21:12

// como un ladrón disfrazado de cartero

A Luis le llega un correo “de AWS”: su cuenta será suspendida. Hace clic y escribe su clave en una página falsa (phishing). El atacante la usa en la consola real… y se estrella con el MFA: no tiene el celular de Luis.

factoresalgo que sabes · algo que tienes · algo que eres
1.2cap. 1 · identidad

La llave que se fue a GitHub

// como dejar copia de la llave de la tienda en la calle

Pedro sube su proyecto a GitHub… con su llave de acceso adentro. Un bot la encuentra en un minuto. Lo salvan tres cosas: la llave tenía mínimo privilegio, GuardDuty avisó y Laura la desactivó en minutos.

Las llaves van en .gitignore; los servicios usan roles, no llaves

1.3cap. 1 · identidad

Quién eres y qué puedes hacer

// como el vigilante: primero tu cédula, después tu lista de permisos

Autenticación (¿quién eres?: clave + MFA) y autorización (¿qué puedes hacer?: las políticas de IAM). Por eso, aunque el atacante tuviera la clave de Luis, sin MFA no entra; y con la llave de Pedro, solo podía lo poquito que la política permitía.

Parte 3de 6

Capítulo 2: el wifi del café

Laura revisa pedidos desde un café. ¿Quién más está escuchando? Y si roban un disco, ¿pueden leerlo?

2.1cap. 2 · cifrado

Simétrico y asimétrico

// como una llave para la misma caja vs. candados abiertos que cualquiera puede cerrar

Simétrico: la misma llave cifra y descifra; rapidísimo, pero ¿cómo le mandas la llave a alguien? Asimétrico: repartes candados abiertos (llave pública) y solo tú guardas la llave que los abre (privada).

2.2cap. 2 · cifrado en tránsito

El candado: HTTPS y TLS

// como un sobre sellado en vez de una postal

En el wifi del café, todo lo que viaja por HTTP se puede leer. Con HTTPS, el servidor muestra su certificado y usan cifrado asimétrico para acordar una llave, y simétrico para hablar. ACM emite y renueva esos certificados gratis.

servicioAWS Certificate Manager (ACM)preciogratis en CloudFront y balanceadores
2.3cap. 2 · integridad

Hash: la huella de los datos

// como una huella digital: identifica, pero no reconstruye a la persona

Un hash convierte cualquier dato en una huella de tamaño fijo. Mismo dato, misma huella; un cambio mínimo, huella totalmente distinta; y no se puede devolver. Así se guardan las claves y así se sabe si un archivo fue alterado.

2.4cap. 2 · cifrado en reposo

El disco que nadie puede leer

// como una caja fuerte que guarda la llave de las otras llaves

Un snapshot del disco de la tienda se compartió por error. Pero estaba cifrado con KMS: sin permiso para usar la llave, el atacante solo ve ruido. KMS guarda la llave maestra en hardware especial y anota cada vez que alguien la usa.

con un clicEBS · S3 · RDS · DynamoDBauditoríacada uso queda en CloudTrail
2.5cap. 2 · secretos

Las claves no van en el código

// como no pegues la clave del cajero en la pared

La clave de la base de pedidos estaba escrita en el código. Secrets Manager la guarda cifrada con KMS, la entrega solo a quien IAM permite y la cambia sola cada cierto tiempo, sin tocar la aplicación.

Parte 4de 6

Capítulo 3: la web bajo ataque

23:40. Peticiones raras contra la tienda, un bot que no para y, a medianoche, una avalancha.

3.1cap. 3 · la red

Security Group vs. NACL

// como el portero de tu puerta y la reja de la calle

El Security Group protege cada instancia, solo permite y recuerda la conversación (stateful). La NACL protege toda la subred, permite y niega y no recuerda nada (stateless): con ella Laura bloquea la IP del bot en toda la red.

3.2cap. 3 · la aplicación

AWS WAF: el filtro delante de tu web

// como el detector de metales a la entrada del centro comercial

A las 23:40 llegan peticiones con patrones de ataque conocidos y un bot pide cientos por minuto. El WAF las revisa antes de que lleguen a la tienda: reglas que AWS mantiene al día, límite por IP y lista negra.

reglasadministradas · límite por IP · lista negramodocontar o bloquear
3.3cap. 3 · disponibilidad

Medianoche: la avalancha

// como mil personas fingiendo hacer fila para que tus clientes no entren

Un DDoS lanza millones de peticiones para tumbar la tienda. CloudFront reparte el golpe entre cientos de ubicaciones y AWS Shield Standard (gratis) filtra los ataques de red más comunes. La tienda sigue vendiendo.

main.tf (S3 privado + CloudFront + WAF)
# =====================================================================
#  Rojo vs. azul: tu web protegida con WAF · Esumer · Cloud Computing, Redes y Ciberseguridad
#  Bucket S3 PRIVADO + CloudFront (HTTPS) + AWS WAF con reglas administradas por AWS.
#  Solo se prueba contra TU propia web, en TU propia cuenta.
#
#  Uso (terminal de VS Code, carpeta con main.tf e index.html):
#    terraform init
#    terraform apply                         (modo "observar": el WAF cuenta, no bloquea)
#    terraform apply -var="modo=bloquear"    (ahora el WAF bloquea con 403)
#    terraform apply -var-file="bloqueo.tfvars"   (lista negra: te bloqueas a ti)
#    terraform destroy                       (al final: el WAF cobra por hora)
# =====================================================================

terraform {
  required_providers {
    aws = { source = "hashicorp/aws", version = "~> 6.0" }
  }
}

provider "aws" {
  region = "us-east-1" # el WAF de CloudFront siempre vive en us-east-1
}

# ---------- 0 · El interruptor del equipo azul
variable "modo" {
  type        = string
  default     = "observar"
  description = "observar = el WAF solo cuenta los ataques · bloquear = los frena con 403"
  validation {
    condition     = contains(["observar", "bloquear"], var.modo)
    error_message = "modo debe ser observar o bloquear."
  }
}

# ---------- 1 · El bucket: la bodega de objetos (nombre único en el mundo)
resource "aws_s3_bucket" "web" {
  bucket_prefix = "tienda-waf-" # AWS le agrega un sufijo para que sea único
  force_destroy = true      # permite borrarlo aunque tenga archivos (solo para el lab)
  tags          = { Name = "tienda-waf" }
}

# ---------- 2 · Candado: bloqueo de acceso público (el bucket queda privado)
resource "aws_s3_bucket_public_access_block" "web" {
  bucket                  = aws_s3_bucket.web.id
  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}

# ---------- 3 · El objeto: tu página (sale del archivo index.html de esta carpeta)
resource "aws_s3_object" "index" {
  bucket       = aws_s3_bucket.web.id
  key          = "index.html"
  source       = "index.html"
  etag         = filemd5("index.html") # si cambias el archivo, Terraform lo vuelve a subir
  content_type = "text/html; charset=utf-8"
}

# ---------- 4 · La credencial de CloudFront para leer el bucket (OAC)
resource "aws_cloudfront_origin_access_control" "oac" {
  name                              = "oac-${aws_s3_bucket.web.id}"
  origin_access_control_origin_type = "s3"
  signing_behavior                  = "always"
  signing_protocol                  = "sigv4"
}


# ---------- La lista negra: IPs que el equipo azul decide bloquear
variable "ips_bloqueadas" {
  type        = list(string)
  default     = []
  description = "IPs con /32, por ejemplo [\"181.50.10.20/32\"]"
}

resource "aws_wafv2_ip_set" "lista_negra" {
  name               = "lista-negra"
  scope              = "CLOUDFRONT"
  ip_address_version = "IPV4"
  addresses          = var.ips_bloqueadas
}

# ---------- 5 · El escudo: AWS WAF con reglas que AWS mantiene al día
resource "aws_wafv2_web_acl" "escudo" {
  name  = "escudo-tienda"
  scope = "CLOUDFRONT"
  default_action {
    allow {}
  }

  # Regla 0: la lista negra de IPs (siempre bloquea)
  rule {
    name     = "lista-negra"
    priority = 0
    action {
      block {}
    }
    statement {
      ip_set_reference_statement {
        arn = aws_wafv2_ip_set.lista_negra.arn
      }
    }
    visibility_config {
      cloudwatch_metrics_enabled = true
      metric_name                = "lista-negra"
      sampled_requests_enabled   = true
    }
  }

  # Regla 1: ataques comunes (XSS, rutas raras, tamaños sospechosos)
  rule {
    name     = "ataques-comunes"
    priority = 1
    override_action {
      dynamic "count" {
        for_each = var.modo == "observar" ? [1] : []
        content {}
      }
      dynamic "none" {
        for_each = var.modo == "bloquear" ? [1] : []
        content {}
      }
    }
    statement {
      managed_rule_group_statement {
        vendor_name = "AWS"
        name        = "AWSManagedRulesCommonRuleSet"
      }
    }
    visibility_config {
      cloudwatch_metrics_enabled = true
      metric_name                = "ataques-comunes"
      sampled_requests_enabled   = true
    }
  }

  # Regla 2: inyección SQL
  rule {
    name     = "inyeccion-sql"
    priority = 2
    override_action {
      dynamic "count" {
        for_each = var.modo == "observar" ? [1] : []
        content {}
      }
      dynamic "none" {
        for_each = var.modo == "bloquear" ? [1] : []
        content {}
      }
    }
    statement {
      managed_rule_group_statement {
        vendor_name = "AWS"
        name        = "AWSManagedRulesSQLiRuleSet"
      }
    }
    visibility_config {
      cloudwatch_metrics_enabled = true
      metric_name                = "inyeccion-sql"
      sampled_requests_enabled   = true
    }
  }

  # Regla 3: demasiadas peticiones desde una misma IP (frena bots y fuerza bruta)
  rule {
    name     = "limite-por-ip"
    priority = 3
    action {
      dynamic "count" {
        for_each = var.modo == "observar" ? [1] : []
        content {}
      }
      dynamic "block" {
        for_each = var.modo == "bloquear" ? [1] : []
        content {}
      }
    }
    statement {
      rate_based_statement {
        limit                 = 100 # peticiones por IP
        evaluation_window_sec = 60  # en 1 minuto
        aggregate_key_type    = "IP"
      }
    }
    visibility_config {
      cloudwatch_metrics_enabled = true
      metric_name                = "limite-por-ip"
      sampled_requests_enabled   = true
    }
  }

  visibility_config {
    cloudwatch_metrics_enabled = true
    metric_name                = "escudo-tienda"
    sampled_requests_enabled   = true
  }
}

# ---------- 6 · CloudFront: la vitrina con candado (HTTPS + certificado) y el escudo puesto
resource "aws_cloudfront_distribution" "cdn" {
  enabled             = true
  default_root_object = "index.html"
  price_class         = "PriceClass_100"
  comment             = "Mi web en S3 con HTTPS y WAF"
  web_acl_id          = aws_wafv2_web_acl.escudo.arn # el escudo va delante de la web

  origin {
    domain_name              = aws_s3_bucket.web.bucket_regional_domain_name
    origin_id                = "s3-mi-web"
    origin_access_control_id = aws_cloudfront_origin_access_control.oac.id
  }

  default_cache_behavior {
    target_origin_id       = "s3-mi-web"
    viewer_protocol_policy = "redirect-to-https" # http -> https siempre
    allowed_methods        = ["GET", "HEAD"]
    cached_methods         = ["GET", "HEAD"]
    cache_policy_id        = "4135ea2d-6df8-44a3-9df3-4b5a84be39ad" # CachingDisabled: ves tus cambios al instante (en producción se usa caché)
  }

  restrictions {
    geo_restriction { restriction_type = "none" }
  }

  viewer_certificate {
    cloudfront_default_certificate = true # certificado HTTPS de *.cloudfront.net
  }
}

# ---------- 7 · Permiso: SOLO esta distribución de CloudFront puede leer el bucket
data "aws_iam_policy_document" "solo_cloudfront" {
  statement {
    actions   = ["s3:GetObject"]
    resources = ["${aws_s3_bucket.web.arn}/*"]
    principals {
      type        = "Service"
      identifiers = ["cloudfront.amazonaws.com"]
    }
    condition {
      test     = "StringEquals"
      variable = "AWS:SourceArn"
      values   = [aws_cloudfront_distribution.cdn.arn]
    }
  }
}

resource "aws_s3_bucket_policy" "web" {
  bucket     = aws_s3_bucket.web.id
  policy     = data.aws_iam_policy_document.solo_cloudfront.json
  depends_on = [aws_s3_bucket_public_access_block.web]
}
